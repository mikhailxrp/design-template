# design-template — правила для Claude Code

Это универсальный дизайн-конвейер (UI/UX). Он превращает бриф или скриншоты в
токены, дизайн-систему и прототип, которые потом идут в вёрстку, WordPress или
интернет-магазин. Как пользоваться человеку — см. `README.md`.

Общайся с пользователем на **русском языке**. Пользователь — Михаил,
разработчик: хочет понимать, что строится, и держать процесс под контролем.

## Команды (порядок)

Полный путь:
`/ux-brief` → `/ux-flows` → `/design-direction` → `/design-tokens` →
`/design-system` → `/prototype` → `/design-review`

Быстрый путь (только скриншоты в `00-input/refs/`):
`/design-direction` → `/design-tokens` → `/design-system` → (`/prototype`) →
`/design-review`

Команды лежат в `.claude/commands/`. Каждая проверяет входные файлы и, если
предыдущего шага нет, называет, какую команду запустить, и останавливается.

## Типы проектов

`/ux-brief` определяет тип (лендинг, многостраничный сайт, магазин, блог,
сервис/веб-приложение, кабинет покупателя, портфолио, другое; можно
несколько). `/design-system` по типу подключает пакет компонентов поверх
базы (`assets/css/packs/`). Тип не определён — база + лендинг, допущение
записать.

Чем делать зависит от аудитории: экраны для клиентов (включая кабинет
покупателя) — чистый HTML/CSS на компонентах системы; админка для
сотрудников (`meta.admin = true`) — Tabler с подменой токенов, готовые
компоненты Tabler не дублировать.

## Принцип: делай, а не допрашивай

- Сначала делай, потом показывай. Человек поправит готовое быстрее, чем
  ответит на анкету.
- Вопросы — только если без ответа нельзя продолжить, **один раз, до 3
  пунктов** за запуск.
- Недостающее принимай разумно и помечай:
  `[измерено]` (снято скриптом с пикселей), `[оценено]` (на глаз),
  `[решено]` (сказал человек), `[допущение]` (твоя гипотеза),
  `[факт]` / `[из брифа]` (взято из документов).
- Не выдавай оценку за измерение. Не придумывай данные: нет — пиши «не
  известно» и выноси в «Пробелы».
- В конце каждой команды — короткий итог по шаблону команды, без повторов
  уже сказанного.

## Источник правды

- `.docs/design/tokens.json` — единственный источник цветов, шрифтов,
  размеров, отступов, радиусов, теней.
- `assets/css/base/vars.css` и `assets/css/admin-theme.css` **генерируются**
  скриптом `tools/build_tokens.py`. Руками не править. Нужна правка —
  меняй `tokens.json` и запускай:
  `python tools/build_tokens.py`
- Оттенки `*-hover`, `*-active`, `on-*`, `*-text`, `*-soft` считает скрипт, в
  `tokens.json` их не пишут.
- Если у админки своя палитра (например, публичная часть тёмная, а админка
  светлая), её источник правды — `.docs/design/tokens-admin.json`
  (`meta.admin = true`), а `admin-theme.css` собирает
  `python tools/build_admin_tokens.py`. В основном `tokens.json` тогда
  `meta.admin = false` — иначе `build_tokens.py` перезапишет тему админки
  цветами публичной части.
- `primary` (цвет бренда с референса) при проблемах контраста **не меняется**:
  правятся зависимые токены (`text`, `text-muted`, `border`, `bg`, `surface`),
  каждая правка — в `meta.adjustments`, максимум 2 итерации.

## Правила кода

1. В CSS компонентов **нет жёстких значений** цвета, радиуса, тени, шрифта.
   Только `var(--...)`. Исключения: `0`, `1px` для границы, `100%`, `auto`.
2. **BEM** (`.btn`, `.card__title`, `.btn--primary`). Без `!important`, без
   стилей по id, глубина вложенности не больше двух уровней.
3. **Mobile-first**: базовые стили для телефона, `min-width` расширяет.
4. **Состояния обязательны**: default, hover, active, `:focus-visible`,
   disabled; у форм — error и success; у списков — loading и empty.
5. **Доступность**: зона нажатия ≥ 44×44px, видимый фокус
   (`--focus-ring`), базовый текст ≥ 16px, контраст ≥ 4.5:1 для текста и
   ≥ 3:1 для элементов, ошибка = цвет + текст/иконка,
   `prefers-reduced-motion` уважается.
6. Ссылки и ошибки красить `--color-*-text`, текст на кнопках —
   `--color-on-*`.
7. **Без библиотек и CDN** в публичной части: чистый HTML/CSS, vanilla JS
   только где без него нельзя. Шрифты — своими файлами `.woff2` в
   `assets/fonts/`. Админка — Tabler с подменой токенов
   (`admin-theme.css`, затем `admin.css` подключаются **после** `tabler.min.css`;
   `admin.css` — ручные поправки Tabler под эти правила: 16px, 44px, фокус,
   контраст статусов). Tabler лежит
   локально в `assets/vendor/tabler/` (версия — в `VERSION.md`), не с CDN.
8. В страницах прототипа **нет** `style=""` и `<style>`. Нужного компонента
   нет — сначала добавь его в дизайн-систему, потом используй.
9. Семантическая разметка: один `h1`, `label` у каждого поля, `alt` у
   изображений, `button` для действий, `a` для переходов.
10. Тексты в прототипе правдоподобные, не «Lorem ipsum». Заглушки
    перечисляй в итоге.

## Структура

```
00-input/            ← исходники человека (refs/ — скриншоты, бриф, ТЗ)
.docs/               ← документы: ux-brief, ux-flows, design/*
  design/            ← direction, tokens.json, tokens-admin.json, tokens-report*, review, screens/
assets/              ← css/ (base, components, packs, admin-theme), fonts/, js/, vendor/tabler/, design-system/
prototypes/          ← HTML-прототип экранов
tools/               ← palette.py (цвета со скриншота), build_tokens.py (сборка CSS),
                       build_admin_tokens.py (тема Tabler из tokens-admin.json)
.claude/commands/    ← 7 команд конвейера
```

Файлы человека в `00-input/` не изменяй. Существующие документы
**дополняй**, ручные правки человека сохраняй.

## Инструменты

- `python tools/palette.py 00-input/refs/<файл> --json` — измерить цвета на
  скриншоте (нужен Pillow: `pip install pillow`). Роли цветов в выводе —
  эвристика, проверяй по смыслу.
- `python tools/build_tokens.py [--strict]` — собрать `vars.css`,
  `admin-theme.css`, `tokens-report.md`. `--strict` возвращает код 3, если
  есть пары ниже порога контраста.
- `python tools/build_admin_tokens.py [--strict]` — собрать только
  `admin-theme.css` и `tokens-report-admin.md` из `tokens-admin.json`;
  `vars.css` не трогает. Сверяет имена переменных с
  `assets/vendor/tabler/css/tabler.min.css`: после обновления Tabler в отчёте
  не должно быть «не найдены переменные».
- В консоли Windows скрипты печатают кириллицу кракозябрами — запускать с
  `PYTHONIOENCODING=utf-8`.
- Нет Python или Pillow — не останавливайся: оцени на глаз, пометь
  `[оценено]` и добавь в «Пробелы».

## Чего не делать

- Не менять `vars.css` и `admin-theme.css` руками.
- Не добавлять компоненты «на всякий случай» (YAGNI): только то, что нужно
  пакету проекта и экранам.
- Не копировать дизайн референса пиксель в пиксель: берём принципы
  (типографика, воздух, иерархия), а не чужой бренд и контент.
- Не скачивать шрифты и изображения из сети: положить файлы должен человек,
  команда называет какие. Библиотеки (Tabler) — только по прямой просьбе,
  из npm с проверкой integrity, с записью версии и источника в `VERSION.md`.
- Не коммитить и не пушить без прямой просьбы.
- Не считать работу готовой без `/design-review` и без пересборки токенов.
