# design-template — как сделать дизайн сайта по шагам

Это набор команд для Claude Code. Он помогает сделать **дизайн любого сайта**
(магазин, лендинг, блог, личный кабинет) и получить на выходе готовые файлы
для вёрстки.

Объяснение для 10-летнего: **как построить дом**.

| В доме | В дизайне |
|---|---|
| Узнать, кто будет жить | `/ux-brief` — для кого сайт |
| Нарисовать план комнат | `/ux-flows` — какие страницы и как между ними ходят |
| Выбрать стиль | `/design-direction` — настроение, цвета, шрифты |
| Закупить одинаковые кирпичи | `/design-tokens` — точные цвета, размеры, отступы |
| Собрать мебель из кирпичей | `/design-system` — кнопки, поля, карточки |
| Обставить комнаты | `/prototype` — готовые страницы из мебели |
| Позвать строгого проверяющего | `/design-review` — что неудобно или сломано |

---

## Какой путь выбрать

Спроси себя: **что у меня есть?**

```
У меня есть только картинки (скриншоты сайтов, которые нравятся)
        │
        ▼
   БЫСТРЫЙ ПУТЬ  (3–4 шага)

У меня сайт с нуля: есть идея, бриф или ТЗ
        │
        ▼
   ПОЛНЫЙ ПУТЬ   (7 шагов)
```

### Быстрый путь (по скриншотам)

```
картинки → direction → tokens → system → (prototype) → review
```

### Полный путь (с нуля)

```
ux-brief → ux-flows → direction → tokens → system → prototype → review
```

### Для каких сайтов подходит

Тип сайта команда определяет сама. В дизайн-системе к общим деталям
(кнопки, поля, карточки) добавляется набор под тип:

| Тип | Что добавляется |
|---|---|
| Интернет-магазин | карточка товара, цена, корзина, фильтры, оформление заказа |
| Лендинг | первый экран, преимущества, отзывы, тарифы, вопросы-ответы, форма |
| Многостраничный сайт | подменю, страница услуги, «о компании», контакты |
| Блог | карточка статьи, оформление статьи, теги, автор |
| Кабинет покупателя | заказы и их статусы, адреса, профиль, избранное |
| Сервис, веб-приложение, админка | боковое меню, таблицы с действиями, фильтры, мастер из шагов |
| Портфолио | карточка работы, галерея, «обо мне» |

Типов может быть несколько сразу (магазин + кабинет покупателя + админка).

Чем верстать: экраны для клиентов, включая кабинет покупателя, делаются на
своём чистом HTML/CSS. Админка для сотрудников делается на Tabler с нашими
цветами.

## Что делать — шаг за шагом

Каждый шаг: **запусти команду → дождись ответа → проверь результат → иди дальше**.
Команды пишутся в чат Claude Code в папке `design-template`.

### Шаг 0. Подготовка (один раз)

1. Открой папку `design-template` в VS Code и запусти Claude Code.
2. Проверь, что стоит Python: в терминале `python --version`.
3. Для быстрого пути поставь Pillow: `pip install pillow`.
4. Положи входные материалы:
   - скриншоты → `00-input/refs/`
   - бриф клиента, ТЗ, заметки → `00-input/`

### Шаг 1. `/ux-brief` — для кого сайт *(только полный путь)*

- **Что делает:** читает твои документы и сам выводит, кто пользуется сайтом
  и зачем. Спросит не больше одного раза и только самое главное.
- **Что получится:** `.docs/ux-brief.md`
- **Что сделать тебе:** прочитать, исправить неверное.

### Шаг 2. `/ux-flows` — какие страницы нужны *(только полный путь)*

- **Что делает:** рисует карту страниц и путей человека по сайту.
- **Что получится:** `.docs/ux-flows.md`
- **Что сделать тебе:** посмотреть, не забыто ли что-то важное.

### Шаг 3. `/design-direction` — какой будет стиль

- **Что делает:** смотрит на скриншоты, измеряет настоящие цвета, выбирает
  шрифты и настроение. Нет скриншотов — выберет стиль сам и предложит ещё
  два варианта.
- **Что получится:** `.docs/design/direction.md`
- **Что сделать тебе:** прочитать выжимку. Не нравится — скажи «давай второй».

### Шаг 4. `/design-tokens` — точные числа

- **Что делает:** превращает стиль в таблицу: какие цвета, размеры, отступы.
  Сам проверяет, чтобы текст было видно (контраст), и сам чинит, если плохо.
- **Что получится:**
  - `.docs/design/tokens.json` — главная таблица (всё остальное берётся из неё)
  - `assets/css/base/vars.css` — готовые переменные для CSS
  - `assets/css/admin-theme.css` — цвета для админки (если она нужна)
  - `.docs/design/tokens-report.md` — отчёт: что проверено, что поправлено
- **Что сделать тебе:** глянуть, что написано в «Что я поправил сам».
- **Важно:** `vars.css` и `admin-theme.css` руками не править. Хочешь изменить
  цвет — меняй `tokens.json` и запусти `/design-tokens` ещё раз.
- **Если у админки своя палитра** (например, сайт тёмный, а админка светлая):
  - её цвета лежат отдельно в `.docs/design/tokens-admin.json`;
  - `admin-theme.css` собирается командой `python tools/build_admin_tokens.py`,
    отчёт — `.docs/design/tokens-report-admin.md`;
  - в `tokens.json` тогда `meta.admin = false`, иначе `build_tokens.py`
    перезапишет тему админки цветами сайта.
- **Tabler для админки** лежит в `assets/vendor/tabler/` (версия и источник —
  в `VERSION.md` там же). Скрипты сверяют с ним имена переменных.

### Шаг 5. `/design-system` — кнопки, поля, карточки

- **Что делает:** делает набор готовых деталей сайта из чисел шага 4.
- **Что получится:**
  - `assets/css/components/` — по файлу на каждую деталь
  - `assets/css/packs/` — детали под твой тип сайта (магазин, лендинг…)
  - `assets/css/main.css` — один файл, который подключает всё
  - `assets/design-system/index.html` — **страница-витрина**, где все детали видны
  - если есть админка на Tabler: `assets/css/admin.css` (поправки Tabler под наши
    правила) и витрина `assets/design-system/admin.html`
- **Что сделать тебе:** открыть витрину в браузере и посмотреть, нравится ли.
- **Что положить руками:** файлы шрифтов `.woff2` → `assets/fonts/`
  (команда напишет какие).

### Шаг 6. `/prototype` — готовые страницы

- **Что делает:** собирает настоящие страницы из деталей шага 5, со всеми
  состояниями (пусто, ошибка, успех) и рабочими ссылками.
- **Что получится:** папка `prototypes/` с `index.html` (оглавление) и по
  файлу на каждую страницу.
- **Что сделать тебе:** открыть `prototypes/index.html`, пройти главный путь
  мышкой, как посетитель.

### Шаг 7. `/design-review` — строгая проверка

- **Что делает:** проверяет по-честному: виден ли текст, нажимаются ли
  кнопки пальцем, не вылезает ли что-то на телефоне, нет ли тупиков.
- **Что получится:** `.docs/design/review.md` со списком: 🔴 блокеры,
  🟠 важное, 🟡 мелочи, и вердикт.
- **Что сделать тебе:** сказать, какие пункты исправить. Исправили → запусти
  `/design-review` снова. **Идти дальше можно, когда блокеров 🔴 нет.**

## Что получается на выходе (вся картина)

```
design-template/
├── 00-input/                  ← сюда ты кладёшь исходники
│   └── refs/                  ← скриншоты
├── .docs/                     ← «бумаги»: решения и отчёты
│   ├── ux-brief.md
│   ├── ux-flows.md
│   └── design/
│       ├── direction.md       ← стиль
│       ├── tokens.json        ← ГЛАВНАЯ ТАБЛИЦА (источник правды)
│       ├── tokens-admin.json  ← палитра админки, если она своя
│       ├── tokens-report.md
│       ├── tokens-report-admin.md
│       └── review.md
├── assets/                    ← «детали»: то, что уйдёт в проект
│   ├── css/
│   │   ├── base/vars.css
│   │   ├── components/
│   │   ├── packs/
│   │   ├── main.css
│   │   └── admin-theme.css
│   ├── fonts/
│   ├── js/
│   ├── vendor/tabler/         ← Tabler для админки (css/, js/, VERSION.md)
│   └── design-system/index.html
├── prototypes/                ← «макеты»: готовые страницы
└── tools/
    ├── palette.py             ← цвета со скриншота
    ├── build_tokens.py        ← tokens.json → vars.css (+ admin-theme.css)
    └── build_admin_tokens.py  ← tokens-admin.json → admin-theme.css
```

Две главные вещи: **`assets/`** (из чего строить) и **`prototypes/`** (как
должно выглядеть).

## Что забрать, чтобы перейти к следующему этапу

Перед переходом: `/design-review` без 🔴, `tokens.json` и `vars.css`
актуальны, шрифты лежат в `assets/fonts/`.

### Вариант А. Верстка лендинга или сайта (lp-template)

| Что забрать | Зачем |
|---|---|
| `assets/` целиком | готовые стили, шрифты, скрипты |
| `prototypes/` | образец каждой страницы, по нему верстается |
| `.docs/design/tokens.json` | чтобы менять цвета в одном месте |
| `.docs/design/direction.md` | чтобы не забыть, почему так выбрано |
| `.docs/ux-flows.md` | список страниц и состояний |

### Вариант Б. Посадка на WordPress

Забираешь то же, что в варианте А. Дальше при посадке:
- `assets/css/` и `assets/fonts/` → в тему;
- блоки `<!-- @include header -->` в прототипе → `header.php`, `footer.php`;
- переменные `vars.css` остаются как есть, ничего не переписывается.

### Вариант В. Интернет-магазин (php-ecommerce)

| Что забрать | Куда |
|---|---|
| `assets/css/`, `assets/fonts/`, `assets/js/` | в `public/assets/` магазина |
| `assets/vendor/tabler/` | Tabler для админки (`css/tabler.min.css`, `js/tabler.min.js`) |
| `assets/css/admin-theme.css`, `assets/css/admin.css` | подключить **после** `tabler.min.css`, в этом порядке |
| `prototypes/` | образец для шаблонов страниц |
| `.docs/design/` и `.docs/ux-flows.md` | в документацию проекта, как опору для ТЗ |

> Куда именно положить в твоей структуре магазина — решаешь ты. Эта таблица —
> предложение, а не закон.

## Золотые правила

1. **Одна таблица.** Цвет меняется только в `tokens.json`, потом `/design-tokens`.
2. **Никаких цветов «в лоб».** В CSS пишем `var(--color-primary)`, а не `#E8590C`.
3. **Сначала телефон.** Верстаем для маленького экрана, потом растягиваем.
4. **Состояния обязательны.** У кнопки есть «нажата» и «выключена», у страницы —
   «пусто» и «ошибка».
5. **Проверка не пропускается.** Без `/design-review` дизайн считается
   неготовым.
6. **Команды не допрашивают.** Они сами принимают решения и помечают
   `[допущение]`. Твоя задача — поправить, если не нравится.

## Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| Команда пишет «файл не найден» | запусти предыдущий шаг, она назовёт какой |
| Нет Pillow | `pip install pillow` |
| Цвета на глаз, а не измерены | положи скриншот в `00-input/refs/` и повтори `/design-direction` |
| Не нравится стиль | скажи «давай второй вариант» и повтори с шага 3 |
| Поменял `tokens.json` руками | запусти `python tools/build_tokens.py` — CSS пересоберётся |
| Поменял `tokens-admin.json` руками | запусти `python tools/build_admin_tokens.py` — пересоберётся `admin-theme.css` |
| Контраст ниже порога | `python tools/build_tokens.py` (или `build_admin_tokens.py` для админки) покажет какие пары; `/design-tokens` исправит сам |
| Обновил Tabler | `python tools/build_admin_tokens.py` — в отчёте не должно быть «не найдены переменные» |
| В консоли Windows кракозябры вместо русского | перед командой: `set PYTHONIOENCODING=utf-8` (cmd) или `$env:PYTHONIOENCODING="utf-8"` (PowerShell) |
